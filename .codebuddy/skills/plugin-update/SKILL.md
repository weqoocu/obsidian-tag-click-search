# Obsidian 插件更新发布

此技能用于 Tag Click Search 插件的版本更新和发布流程。

## 触发条件

当以下情况发生时使用此技能：
- 用户说"更新版本"、"发布新版本"、"升级版本号"
- 完成功能开发后需要发布
- 用户要求重启插件

## 更新流程

### 1. 更新版本号

修改 `manifest.json` 中的 `version` 字段：
- 小功能/修复：递增最后一位（如 1.44.0 → 1.44.1）
- 新功能：递增中间位（如 1.44.0 → 1.45.0）
- 重大更新：递增第一位（如 1.44.0 → 2.0.0）

### 2. 更新功能描述

如果添加了新功能，同步更新 `manifest.json` 中的 `description` 字段，简要描述新增功能。

### 3. 文件位置

```
插件根目录/
├── manifest.json    # 版本号和描述（必须更新）
├── main.js          # 主代码文件
├── data.json        # 用户配置数据（不要修改）
└── package.json     # npm 配置（可选更新）
```

### 4. 提示用户重启插件

更新完成后，提示用户手动重启插件：

**方法一：重启插件**
1. 打开 Obsidian 设置 → 第三方插件
2. 找到 `Tag Click Search`，关闭开关
3. 再次打开开关

**方法二：重载 Obsidian**
- 使用快捷键 `Cmd + P`（Mac）或 `Ctrl + P`（Windows）
- 输入 `reload`，选择 "Reload app without saving"

## 版本号规范

| 更新类型 | 版本变化示例 | 说明 |
|---------|-------------|------|
| 修复 Bug | 1.45.0 → 1.45.1 | 修复问题，无新功能 |
| 新功能 | 1.45.0 → 1.46.0 | 添加新功能 |
| 重大更新 | 1.45.0 → 2.0.0 | 架构变更或不兼容更新 |

## 注意事项

- 不要修改 `data.json`，这是用户的配置数据
- `package.json` 的版本号可以不同步更新（主要用于 npm）
- 确保 `manifest.json` 是有效的 JSON 格式
